# Milestone 1: hardware test plan

**Goal:** confirm that a RasBeacon image boots on your hardware, runs the
setup network and web UI, and that the hotspot radio passes the gate of
**10 devices associated with WPA2/WPA3 for 30 minutes**. We also want power
numbers.

There is **no internet through RasBeacon yet**. Your devices will say
"No internet connection" on its hotspot. That is expected until
milestone 2.

## What you need

- **The board:** a Raspberry Pi 4 or 5 and your TP-Link Archer T3U.
- **The image:** from the latest "Release images" run on GitHub (Actions tab
  → Release images → the newest run → *Artifacts*): `rasbeacon-pi4-…`
  for a Pi 4, `rasbeacon-pi5-…` for a Pi 5. Unzip it to get
  `rasbeacon-<board>-<version>.img.xz`.
- **Tools:** Raspberry Pi Imager, and a USB power meter (USB-C inline type)
  if you have one.
- **Devices:** ideally at least 10 to connect (phones, laptops, tablets,
  watch, a friend's phone...).
- **For the throughput check:** two laptops with `iperf3` (macOS:
  `brew install iperf3`).

Copy the **report template** at the end, fill it in as you go, and paste it
back.

## 1. Flash and first boot

1. Flash the `.img.xz` with Raspberry Pi Imager: *Use custom*, and answer
   **No** to OS customisation.
2. Don't create `setup.txt` yet (it's tested in step 6).
3. Put the card in the Pi, plug the Archer T3U into a **USB 3 (blue) port**
   on a Pi 4 (any port on a Pi 5), then connect power. Note the time.
4. On your iPhone, open Settings → Wi-Fi and wait for
   `RasBeacon-Setup-XXXX`. Note how long it took to appear after power-on.
5. Join it.
   - **Report:** did the "Log in" setup sheet open **by itself**? If not,
     open Safari and go to `http://10.87.0.1`. Does the setup page load?
6. **Report:** do the same check with the Android phone: does the "Sign in
   to network" notification appear by itself?

## 2. Finish setup

1. In the setup page:
   1. Choose an admin password (10+ characters).
   2. Keep or change the hotspot name.
   3. Keep the suggested Wi-Fi password, or choose your own.
   4. Leave the band on **2.4 GHz**.
   5. Tap *Finish setup*.
2. Within about 10 seconds the setup network should disappear and your
   hotspot should appear. Join it with the password.
3. Open `http://10.87.0.1` and log in.
4. **Report:** what the Status page shows under **Wi-Fi radios** (interface,
   role, USB ID for each row) and under **Warnings** (if any).
   - We expect `ap0` = hotspot with USB ID `2357:012d`, and `wlan0` =
     uplink (built-in).

## 3. Hotspot gate: 10 devices for 30 minutes (most important)

1. Connect as many devices as you can to your hotspot. Aim for 10: both
   iPhones, the Android phone, the iPad, both MacBooks, the Apple Watch
   (Settings → Wi-Fi on the watch), plus borrowed or older devices.
2. On the Status page, note **Connected devices (N)**.
3. Leave everything connected for **30 minutes**. Keep the phones' screens
   on or check them occasionally: phones drop idle Wi-Fi to save power, and
   that is not a RasBeacon failure. What matters is that the hotspot stays
   up and devices can rejoin.
4. At the end:
   1. Note the connected count again.
   2. Note whether any device showed "incorrect password", couldn't rejoin,
      or the network vanished.
   3. Go to **System → Download diagnostics** and keep the file.
5. **Report:**
   - the counts at the start and end
   - any drops
   - from the diagnostics file, every line containing `beacon`, `flush`,
     `rtw88`, `timed out` or `hostapd` errors (search the text file)

   If there are none, say so.

> If the Archer T3U fails this gate, the plan is to try the mitigation
> first (a longer beacon interval; I'll ship it in a test build), then
> recommend an MT7612U adapter.

## 4. Radio throughput between two devices (no internet needed)

This measures the hotspot radio on its own. Devices on the hotspot can
reach each other.

1. Put both MacBooks on the hotspot, about 2 m from the Pi.
2. On MacBook A: `iperf3 -s` (the Status page shows its address, e.g.
   10.87.0.23).
3. On MacBook B: `iperf3 -c <A's address> -t 20`, then
   `iperf3 -c <A's address> -t 20 -R`.
4. **Report:** the two `receiver` lines (Mbits/sec).

(Traffic goes MacBook B → Pi → MacBook A, so this is roughly half of what
one device could get. That's fine: it's a baseline.)

## 5. Power (if you have a USB power meter)

Put the meter between the power supply (or power bank) and the Pi.

1. **Idle with devices connected:** at least 5 devices connected, nothing
   downloading, 5 minutes. **Report:** average watts (or volts × amps).
2. **Under load:** while the iperf3 test from step 4 runs. **Report:**
   average watts.
3. **Only if you use a power bank:** after 30 minutes idle, is it still
   on? **Report:** the bank model, and whether it switched off.

## 6. setup.txt (protected setup network)

1. Do a factory reset: System → Factory reset, enter the admin password.
2. After it restarts, confirm `RasBeacon-Setup-XXXX` is back and open.
3. Power off. Put the SD card in your computer. On the `BOOTCONFIG` drive,
   create `setup.txt` containing `setup_password=testing-1234`. Eject and
   boot the Pi.
4. **Report:** the setup network now asks for a password, and
   `testing-1234` works.
5. **Broken file test:**
   1. Power off.
   2. Change the file to `setup_password=short`, and boot.
   3. **Report:** the setup network does **not** appear, and the green LED
      blinks 3 short, 1 long, repeatedly.
6. Delete `setup.txt`, boot, and finish setup again.
7. **Report:** after finishing setup, is `setup.txt` gone from the card?
   (Check on your computer.)

## 7. 5 GHz setting

1. Hotspot page → Band **5 GHz** → Save.
2. **Report:**
   - the hotspot reappears on 5 GHz (on a Mac: Option-click the Wi-Fi icon
     to see the channel)
   - the Status page shows 5GHz channel 36
   - devices can rejoin
   - the Apple Watch will not see a 5 GHz network on older models; that is
     expected
3. Repeat the iperf3 test (step 4) on 5 GHz. **Report:** the receiver
   lines.
4. Switch back to 2.4 GHz.

## 8. Power-cut safety

Three times, pull the power while the Pi is running normally, wait 5
seconds, and plug it back in.

**Report:** each time, did your hotspot come back with the same name and
password, and could you log in?

## 9. Factory reset from a computer

1. Power off. On the `BOOTCONFIG` drive create an empty file named
   `factory-reset` (no extension; on Windows, check that it isn't
   `factory-reset.txt`).
2. Boot.
3. **Report:** the setup network is back, and the `factory-reset` file is
   gone from the card afterwards.

## 10. Optional: SSH, for more detail

Only if you're comfortable with SSH. It helps a lot if the gate in step 3
fails.

1. On the SSH page:
   1. Paste your laptop's public key (for example, from
      `cat ~/.ssh/id_ed25519.pub`).
   2. Tick *Turn on SSH*.
   3. Save.
2. From a laptop on the hotspot, run `ssh root@10.87.0.1` and paste back
   the output of:
   ```sh
   uname -r
   iw dev
   iw list | sed -n '/valid interface combinations/,/^$/p'
   dmesg | grep -i -E 'rtw88|brcmf|usb .*: new' | tail -n 40
   journalctl -b -u rasbeacon-hostapd.service --no-pager | tail -n 40
   ```
3. Turn SSH off again afterwards.

## Optional: Pi Zero 2 W

Same `rasbeacon-pi4` image. The only question for now is whether it boots
at all: the Zero 2 W's boot ROM may not support the image's partition
layout. **Report:** does `RasBeacon-Setup-XXXX` appear within 3 minutes?
If the green LED only flashes a few times and stops, it didn't boot.
