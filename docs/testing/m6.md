# Milestone 6: hardware test plan (updates, HTTPS, reset button)

**Goal:** confirm that a signed update installs and that a bad one can't,
that a failed update rolls back by itself, that HTTPS works, and that the
optional reset button erases everything.

## What you need

- Your Pi 4 + Archer T3U.
- Two release builds **made after the update signing key was set up**
  (see [docs/releasing.md](../releasing.md)): an older one flashed on the
  card, and a newer one's `rasbeacon-pi4-<version>.rbupdate` file on your
  phone or laptop.
- Optional: a push button and two jumper wires (step 5).

Copy the **report template** at the end and fill it in.

## 1. Install an update

1. Flash the older image, finish setup, and connect to the internet.
2. **System** page → **Software**: note the version shown.
3. Choose the newer `.rbupdate` file → **Install update** → confirm.
4. Keep the page open. Uploading over Wi-Fi takes a minute or two, then
   RasBeacon restarts (the hotspot disappears for about 2 minutes).
5. Rejoin the hotspot and open the **System** page again.
6. **Report:**
   - did it show *Updated to <new version>*?
   - are all settings still there (hotspot, saved networks, VPN)?
   - how long from tapping Install until the hotspot was back?

## 2. Bad update files are refused

1. Try to install each of these, one at a time:
   - the `.img.xz` image file renamed to `test.rbupdate`;
   - a `.rbupdate` for the **pi5**;
   - a copy of the good `.rbupdate` with one byte changed near the end (on
     a Mac or Linux:
     `cp good.rbupdate bad.rbupdate && printf 'X' | dd of=bad.rbupdate bs=1 seek=100000000 conv=notrunc`).
2. **Report:** for each, the message shown. RasBeacon must not restart
   for any of them, and the version must stay the same.

## 3. Rollback (optional, needs an SD card reader)

This checks that RasBeacon goes back to the old version if the new one
doesn't come up.

1. Start installing an update as in step 1.
2. As soon as the hotspot disappears (the restart), pull the power, wait 5
   seconds, and plug it back in.
3. **Report:** does RasBeacon come back on the **old** version, and does
   the System page say the update *didn't start correctly*?

## 4. HTTPS

1. **HTTPS** page → tick **Use HTTPS for these settings pages**.
2. After a few seconds, open `https://10.87.0.1/`. Your browser warns
   about the certificate. Open the warning's details and compare the
   SHA-256 fingerprint with the one on the HTTPS page (you may need to
   open the page over plain HTTP in another tab to see it).
3. Continue, log in, and use a few pages.
4. Open `http://10.87.0.1/`: it should send you to HTTPS.
5. **Report:** did the fingerprints match? Did everything work over HTTPS?
   Did `http://` redirect?
6. Untick **Use HTTPS** if you prefer to keep plain HTTP.

## 5. Reset button (optional)

1. Power off. Connect a push button between **pin 11 (GPIO 17)** and
   **pin 9 (ground)** on the Pi's header.
2. Power on and wait until the hotspot is up.
3. Press the button briefly. **Report:** nothing should happen.
4. Hold it for **10 seconds**, then release. **Report:** does RasBeacon
   restart into the setup network (`RasBeacon-Setup-XXXX`) with all
   settings erased?

## 6. Diagnostics and logs don't leak secrets

1. With the VPN and an Enterprise or password-protected uplink saved,
   download **System → Diagnostics**.
2. Search the file for your hotspot password, Wi-Fi passwords, the VPN's
   `PrivateKey` and your eduroam username.
3. **Report:** none of them should appear (usernames only masked, like
   `N***@rutgers.edu`).
