# Milestone 3: hardware test plan (eduroam / WPA-Enterprise)

**Goal:** confirm RasBeacon joins Rutgers' eduroam with the certificate
check on, refuses a server it shouldn't trust, and record whether Rutgers
offers WPA2- or WPA3-Enterprise.

The simulated tests in CI already log in with every method against a test
network. This plan checks the real thing.

## What you need

- Your Pi 4 and Archer T3U, flashed with the latest image (setup again).
- To be on campus, in range of `eduroam`.
- Your NetID and password.
- Rutgers' CA certificates and server name: see
  [docs/eduroam.md](../eduroam.md#example-rutgers-university). Save the
  certificate files on your phone or laptop (whichever you use for the web
  UI).
- Before going to campus: connect RasBeacon to any network once (home
  Wi-Fi, or your phone's hotspot as a Wi-Fi uplink) so its clock is set.
  See the clock note at the end of the eduroam guide.

Copy the **report template** at the end and fill it in.

## 1. Scan

1. Internet page → **Look for nearby networks**.
2. **Report:** the line shown for `eduroam` (for example
   "WPA2-Enterprise, 5 GHz, good (-60 dBm)").

## 2. Join eduroam

1. Tap **Set up eduroam**.
2. Login method: as Rutgers publishes it (if unsure, start with *EAP-TTLS
   with PAP*).
3. Username `NetID@rutgers.edu`, anonymous username
   `anonymous@rutgers.edu`, your password.
4. **CA certificate file:** choose both certificate files.
5. **Login server name:** `*.ruw.rutgers.edu`.
6. **Add to list**, then **Save**. If you have other networks saved, move
   eduroam to the top.
7. Wait up to 30 seconds and check the Status page.
8. **Report:**
   - connected yes/no, and which login method worked (try PEAP if TTLS
     didn't)
   - on the phone (on the hotspot), do websites load?
   - the saved network's line on the Internet page (CA certificate summary)

## 3. WPA2 or WPA3?

1. **System → Download diagnostics.** In the `wpa_cli ... status` section,
   find `key_mgmt=`.
2. **Report:** its value: `WPA2/IEEE 802.1X/EAP` means WPA2-Enterprise;
   `WPA2-EAP-SHA256` or `IEEE 802.1X/EAP-SHA256` means WPA3-Enterprise
   (or WPA2 with stronger keys).
3. While you have the file open, **check privacy:** search for your NetID.
   It should appear only as `N***@rutgers.edu` (masked), and your password
   must not appear at all. **Report:** yes/no.

## 4. A wrong server name is refused

1. On the Internet page, remove eduroam, **Save**, then add it again
   exactly as before but with the server name `wrong.example.edu`.
2. **Save** and wait 30 seconds.
3. **Report:** the Status page should show *The network rejected the
   login* and must **not** connect.
4. Remove it and add it again with the right server name, so you stay
   connected.

## 5. A wrong password is reported

1. Same as step 4, but with the right server name and a wrong password.
2. **Report:** does the Status page show *The network rejected the login*?
3. Fix the password (remove and add again, or type the right one into the
   *New password* box on the saved network) and **Save**.

## 6. Survives a power cut

1. Pull the power, wait 5 seconds, plug back in.
2. **Report:** after about a minute, is eduroam connected again by itself?
